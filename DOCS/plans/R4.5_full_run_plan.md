  background execution (the browser tab must stay open).

**Status, 2026-10-21 (after Deviation 2, main a11f1aa).** The estimates
below assume serial CNN-HMM fitting and unpinned threads, as in the pilot
(aa6758c). Main now fits HMM candidates and restarts in parallel
(`RunnerConfig.hmm_n_jobs = -1`) and pins BLAS/OpenMP to one thread.
Measured CNN-HMM speed-ups on 4 cores (synthetic 40-participant root): 2.07×
and 1.29× (cause of the difference unknown; not measured on Colab). Applying
them to the 50 h of CNN-HMM fitting gives roughly 33–48 A100-hours (≈ 180–260
units): still more than 100 units. The speed-up depends on the runtime's vCPU
count, so S2 must record `nproc` and the hybrid step's time before the draw
sessions are planned. Pilot timings for the other steps were taken without
the thread pin; their pinned cost is unmeasured. This section is the
deviation's cited baseline (commit 0352fb0) and is kept unchanged.

## Summary

## 2. Scaling to the full run

- Pilot sizes (from the log): `full` = 100 participants ("100 test + 0
  middle-band rows"); `primary` = 85 test + 15 middle band ("85 test + 15
  middle-band rows").
- Full run: `primary` = 320, `full` = 400. Scale factors: ×3.76 (primary) and
  ×4.00 (full), assuming cost grows linearly with participants.
- Embeddings and handcrafted already processed all 9,600 crops in the pilot
  (1,600 + 6,000 + 2,000 embedded), so they cost the same. Grad-CAM is held at
  60 s (it uses example crops; an estimate).

What the pilot skipped: the CNN-path permutation tests, `n_cnn = 20` full
retrains, primary set only. From `cnn_null_run` in
`src/analysis/permutation.py`, one draw:

1. retrains the CNN for every family and fold (15 fits) on shuffled inner
   labels, with the same epochs and early stopping;
2. refits the CNN-HMM for word and cursive (10 fits), with full selection and
   Platt calibration;
3. refits the two ensemble LRs and combines them.

One draw gives the null value of all three CNN-path models (`cnn_head_fused`,
`cnn_hmm_fused`, `ensemble`). Cost of one draw = the pilot's primary
`cnn_shuffled` + `hybrid` (404.1 + 2141.9 s) × 3.76 = **9,585 s ≈ 2.66 h on
T4**, of which 8,064 s is CNN-HMM fitting on the CPU.

## 3. Hours and units

A100 speed-up assumption: **2.5× on CNN training only** (cnn, cnn_shuffled,
and the CNN part of each draw). An A100 has about 2.4× a T4's FP32 throughput
(more with TF32), but ResNet18 at batch 32 on small grayscale crops with 2
loader workers is partly limited by data loading. CPU-bound steps, embeddings
(loading-limited), and the hybrid step get 1.0×.

| Part | T4 h | A100 h | Units at 5.4/h | +20% |
|---|---|---|---|---|
| Everything except the draws | 12.13 | 10.98 | 59.3 | 71.2 |
| 20 CNN-path draws | 53.25 | 48.18 | 260.2 | 312.2 |
| **Total** | **65.38** | **59.16** | **319.5** | **383.4** |

**It does not fit in 100 units: about 283 more units are needed** (A100-only,
with buffer). 100 units covers the non-draw part plus roughly the first 2–3
draws.

The LR permutation tests use all cores. If the A100 runtime has more CPU cores
than Kaggle's T4 machine (Kaggle T4 x2 has 4 vCPUs, not verified), those ~4.3 h
would shrink. That changes the total only a little. Session 2 records `nproc`
to settle it.

## 4. CPU-bound work that keeps the A100 idle

About **54.6 of the 59 A100-hours (≈ 295 units)** are CPU-bound:

- CNN-HMM fitting in the hybrid steps and inside every draw: 50 h
- LR permutations: 4.3 h
- handcrafted features: 0.5 h

What can move to a cheaper CPU-only Colab session with the existing runner and
`--steps` (no code change):

- **`handcrafted`:** yes. It has no dependencies.
- **`full/permutation` (LR only):** yes, with `ANALYSIS="full"`,
  `STEPS="permutation"`. It needs embeddings, handcrafted, and `full/baselines`
  finished first: it reads the observed predictions only *after* computing the
  1,000-draw null, so if baselines are missing it fails after hours of work.
- The markers carry over: a marker records only the subset,
  `predict_middle`, and the config hash. The device is in neither the markers
  nor the draw cache's `run_config.json`, so an A100 session skips steps
  finished on CPU.

What would need a code change (not proposed here):

- **Primary LR permutations** run inside the same `primary/permutation` step as
  the CNN-path draws (LR first), so they can't be split off. LR tests also have
  no per-test resume: **every restart of `primary/permutation` (each
  disconnect) recomputes both primary LR tests, about 2 h, before the cached
  draws resume.**
- **CNN-HMM fitting inside a draw** runs interleaved with GPU training in one
  function, so it can't be moved to a CPU session.

Options that need no repo change:

- **Hybrid on a CPU runtime:** the runner accepts `STEPS="hybrid"`,
  `DEVICE="cpu"`, but how long the CPU feature extraction takes is unmeasured.
- **Draw-only cell:** after notebook cells 2–8, type this in a cell yourself:

  ```
  !cd /content/EMHA && python -m src.analysis.permutation --model cnn_head_fused --analysis primary --device cuda
  ```

  Run it in the same kernel after the run-mode cell, so it inherits the
  `OMP/MKL/OPENBLAS_NUM_THREADS=1` pin (Deviation 2).

  It caches all 20 draws in
  `results/final/permutation_runs/primary/seed_42/perm_*.csv` (resumable per
  draw) and runs no LR. The runner's `primary/permutation` then runs the LR
  tests once and reads the cached draws. Costs: no automatic log mirroring and
  no auto-disconnect.

## 6. Disk

- **Checkpoints:** state dict only, about 44.7 MB each (ResNet18 size). Count:
  cnn + cnn_shuffled × 2 sets × 15 = 60, the same as the pilot, so **about
  2.7 GB**, plus 20 small HMM models. Pilot cross-check: the stalled CLI
  download held 1.6 GB of the pilot models zip (a partial figure).
- **Results:** about 100 MB or less (pilot 31.7 MB zipped; embeddings already
  full size; predictions grow about 4×).
- **Draw scratch space:** each draw writes 15 temporary checkpoints
  (~0.67 GB) **into `models/` on Drive**, then deletes them. Files deleted
  through the Colab Drive mount may land in Drive Trash and count against the
  quota, up to about 13 GB over 20 draws (not verified; check Trash after the
  first draw). Pointing the scratch folder at the local disk would need a code
  change.
- **Free Drive space needed:** **≥ 4 GB** if Trash stays empty, **≥ 18 GB** to
  be safe otherwise. The 0.58 GB dataset zip is already uploaded.
