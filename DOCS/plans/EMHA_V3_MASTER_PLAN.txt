What the adviser asked for
  Train the system on each exercise on its own, one at a time (all 24:
  D1-D4, W1_LH ... W5_UC, CS1-CS5), and get a result for every exercise.

What v3 is
  v1 trains one model per task FAMILY (drawing / word / cursive) on all of
  that family's crops and averages crop probabilities per participant. v3
  trains one model per EXERCISE. Each exercise gives exactly one image per
  participant, so every v3 model is a plain participant-level classifier.
  v3 reports a 24-row table (one row per exercise) for four model types,
  plus a few combinations that are fixed in writing before anything runs.
  Same participants, folds, labels, inner split, seed and 0.5 threshold as
  v1 and v2. Nothing is re-cropped, re-preprocessed or re-embedded.

What does NOT change
  - v1 (cnn_hmm_fused/fused) stays the primary model (Deviation 4).
    v2 stays exploratory (Deviation 5). v3 is exploratory (Deviation 6).
  - No v1/v2 file, output, tag or number is touched. v3 writes only to v3
    paths (section 5). RESULTS.txt, model_comparison.*, RUN_LOG.csv and the
    pipeline step markers are never written by v3.
  - DATASET/, raw-3Page, raw-4Page, folds.csv, labels.csv: read-only.

      filtered to one cell, with the same transforms, batch size, workers
      and seeded generator. build_loaders stays untouched.
  F3  run_hybrid._fold(save=True) writes HMMs under models/hmm/<run>/, which
      is v1's folder, and it does not return inner-val predictions. Fix: v3
      does not call _fold. It repeats _fold's steps in its own function using
      the reusable pieces (extract_set, select_hmm, fit_final, _check_split)
      and saves to models/hmm_v3/.
  F4  The synthetic fixture (src/utils/synthetic.py) writes
      handcrafted_participant.csv but NOT handcrafted_crop.csv. Fix: the v3
      tests write their own crop-level fixture; synthetic.py is not edited.
  F5  CNN draws are cached as perm_0000.csv (4 digits), and a runs folder
      needs its own run_config.json or scripts/merge_draws.py rejects it.
      Fix: v3 draws follow exactly that layout.
  Also new in rev. 2:
  - The CNN-path permutation decision (D2) is made from compute timing only,
    after the main training run and BEFORE any v3 metric exists. The rule is
    written into Deviation 6 now, and the code refuses to evaluate until the

  - A "word_cursive" combination is added so v3 has a like-for-like row

  Honest expectation for v3. Each per-exercise model trains on about 217
  images (one per inner-train participant) and early-stops on about 39.
  That is 4x to 15x less data per model than the v1 family models. Most
  exercises will probably sit near chance. With 24 exercises, about one can
  look "significant" at p < 0.05 by luck, which is why the LR rows get an
  FDR correction and the CNN path gets one pre-declared combined test. v3
  is not tuned toward the 70-80% target. If no row reaches it, the paper
  says so, and the contribution stays the FINALE dataset and the leak-free
  pipeline. The per-exercise table is still useful: it shows which tasks
  carry any signal, which is what the adviser asked.

3. LEAKAGE RULES (each one is enforced in code or by a test)
================================================================================

  L1  Participant is the unit. One image per participant per exercise, so a
      participant can never sit on both sides of any split.
  L2  Same outer folds (folds.csv SHA-256
      40403812420cde0e1f7d1980ce02ad0f77c531fdf59aab62b7987ca4b90751bf),
      same labels (labels.csv SHA-256
      694d360091e28dc331422cf7171b8e3afcf5dda16545e7ad5b2a9291204d3006),
      same primary set (splits.analysis_ids) for every exercise.
  L3  Same inner split for every exercise in a fold:
      inner_split(train, labels, config.cv.inner_val_fraction,
      config.training.seed + fold), always drawn on TRUE labels (also in
      permutation draws, exactly as run_cnn._fit_fold). Checked against the
      IDs stored in every v3 CNN checkpoint (run_hybrid._check_split).
  L4  assert_no_leakage(train, test) and
      assert_no_leakage(inner_train, inner_val, test) in every
      (exercise, fold), in every model.
  L5  Fit on inner-train / outer-train only: CNN weights (inner-train),
      HMM scaler/PCA/HMMs (inner-train), LR scaler/PCA/C (outer-train, C by
      inner CV inside fit_lr, as in run_baselines).
  L6  Inner-val is used only for CNN early stopping, HMM setting selection,
      Platt calibration, and the "selected exercise" rule. Never test.
  L7  Threshold = config.aggregate.threshold (0.5). No per-exercise
      thresholds.
  L8  Combinations are plain equal-weight means. Nothing is learned.
  L9  Picking the best row of the 24-row table and calling it "the result"
      is selection on test. The only best-exercise model v3 reports is
      cnn_hmm_v3_selected, chosen per fold on inner-val only. Inner-val is
      small (about 39 participants per fold), so the chosen exercise can
      change between folds by chance. That makes the selected row noisy,
      not biased: nothing is chosen on test.
  L10 Permutation draws shuffle outer-train labels only
      (run_cnn.shuffled_labels with permutation_seed(seed, draw, fold));
      test labels stay true.
  L11 Handcrafted features: handcrafted_crop.csv imputes a missing crop
      value from the SAME participant's other crops in that family (or the
      fixed fallback 0.0). No cross-participant or label information. It
      does mean an imputed value in one exercise comes from that person's
      other exercises, so preflight prints the imputed-value count per
      exercise and the paper reports it. Embeddings are frozen ImageNet
      weights (no labels).
  L12 Preflight: zero dropped crops (qc_log.csv) inside the primary set,
      exactly one processed crop per (participant, exercise).
  L13 No reruns after seeing results. A bug fix is logged as an addendum
      under Deviation 6, rerun once, and both outputs are reported.
  L14 v3 never writes outside its own paths. Checked by scripts/hash_tree.py
      on the Drive output root before and after (Phase 3 and Phase 10).

6. 2026-10-27 — Exploratory analysis added at the adviser's request, after
   all v1 and v2 results were seen: v3, per-exercise training. Each of the
   24 FINALE exercises (src/data/crop_manifest.py ALL_CELLS: D1-D4,
   W1_LH ... W5_UC, CS1-CS5) is modelled on its own, one image per
   participant, one model per (exercise, outer fold), on the primary set
   and folds.csv. The inner split is run_cnn's (inner_split, 15%, seed
   TrainingConfig.seed + fold, drawn on the true labels) and is the same
   for all 24 exercises in a fold. Per-exercise models: lr_handcrafted_v3
   (the exercise's rows of results/features/handcrafted_crop.csv, fit_lr as
   in run_baselines; imputed values come only from the same participant's
   other crops of that family and are counted and reported), lr_embeddings_v3
   (the exercise's cached frozen ResNet18 embedding, fit_lr with PCA),
   cnn_head_v3 (fine-tuned ResNet18 as in run_cnn, CNNConfig and
   TrainingConfig unchanged, trained on that exercise's crops only) and
   cnn_hmm_v3 (run_hybrid's layer3 column-sequence HMM on that exercise's
   cnn_head_v3 checkpoint, HybridConfig grid unchanged, setting chosen and
   Platt-calibrated on the inner validation participants; drawing
   exercises included). Combinations fixed before any v3 result:
   cnn_head_v3_fused and cnn_hmm_v3_fused, the equal-weight mean of the
   per-exercise probabilities over the drawing, word and cursive exercises,
   over word + cursive (word_cursive, the counterpart of v1's fused
   CNN-HMM) and over all 24 (all24); cnn_hmm_v3_selected, in each outer
   fold the single exercise with the highest inner-validation participant
   macro-F1 of cnn_hmm_v3 (ties in ALL_CELLS order), applied to that
   fold's test participants. The inner validation set is small (about 39
   participants per fold), so the selected exercise may differ between
   folds by chance; this makes cnn_hmm_v3_selected noisy but does not
   involve any test participant. A participant is SAD when P(SAD) >= 0.5.
   Nothing is fit, selected, weighted or calibrated on outer-test
   participants. Reported for every v3 row: macro-F1, accuracy, balanced
   accuracy and ROC-AUC with 2,000-resample bootstrap CIs (seed 42), the
   majority baseline, every fold and the confusion matrix; paired macro-F1
   differences vs lr_handcrafted/all for every row, the all24 row also vs
   cnn_hmm_fused/fused, lr_embeddings/concat, cnn_head_fused/fused and
   cnn_hmm_v2/task_order, and each family row vs the v1 model of the same
   kind and family where it exists. Permutation tests: each per-exercise LR
   model with N = 1,000 (permutation_seed(seed, draw, fold) as in
   src/analysis/permutation.py) and Benjamini-Hochberg FDR (q = 0.05)
   across the 24 exercises within each LR model; one CNN-path test,
   cnn_hmm_v3_fused/all24, with N = 20 full retrains of all 24 exercises,
   run only if 20 x (main cnn step time + main hmm step time), read from
   the run logs before any v3 metric is computed, is at most BUDGET_HOURS
   GPU-session hours; otherwise no CNN-path test is run and CNN rows report
   bootstrap CIs only. The decision is recorded as an addendum to this
   deviation and committed before evaluation. Per-exercise CNN rows from
   the draws are descriptive only. v1 remains the primary model and v2
   stays exploratory; their outputs are not changed (SHA-256 snapshot of
   the output root before and after, scripts/hash_tree.py); v3 writes only
   to v3 paths, is labeled EXPLORATORY everywhere and is reported in full
   whatever its result. Implementation note: the new PerTaskV3Config
   section is excluded from the pipeline runner's config fingerprint, like
   HybridV2Config, so v1's step markers stay valid. Reason: the adviser
   asked that each exercise be trained and evaluated one by one, to show
   which tasks carry information about the self-reported state. Real
   results seen: all v1 and v2 results; no v3 result exists.
