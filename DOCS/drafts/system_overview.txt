4.5 System Overview

EMHA is a set of modules that turns one respondent's completed FINALE assessment into a prediction. The input is the scanned drawing page, the scanned writing page, and the self-report responses, which supply the label. The output is HAPPY or SAD with a probability P(SAD). It predicts the concurrently self-reported state, not a clinical diagnosis.

Basis of the hypothesis. Handwriting is a coordinated motor and cognitive act, and motor models treat the trace as the output of the neuromuscular system (Plamondon & Maarse, 1989). A change in the writer's state can therefore appear in size, slant, baseline, spacing, and pressure (Fairhurst et al., 2015; Kedar et al., 2015). EMOTHAW showed that handwriting and drawing tasks carry information about emotional state, but it used tablets that record timing and pressure (Likforman-Sulem et al., 2017). Most handwriting exists only on paper, and offline studies are few (Section 2.6). Whether the static scanned image alone still carries this information became the primary hypothesis (Section 1.2.3): the CNN-HMM hybrid classifies unseen writers of the primary set as happy or sad with a higher macro-averaged F1-score than expected by chance, as judged by a permutation test. Earlier work relied on handcrafted features; because writing is produced from left to right and CNN-HMM hybrids have worked on images with sequential structure (Goumiri et al., 2023), the secondary hypothesis is that the CNN-HMM hybrid obtains a higher macro-averaged F1-score than the logistic regression baseline on handcrafted features.

Labeling module. It reads each respondent's label and adjusted total verbatim from the exported scoring sheet and never recomputes them. The label follows the cutoff of 72 on the adjusted total (Section 3.2). The 20% of respondents closest to the cutoff, the 80 with totals of 70 to 74, form the middle band set aside from the primary set.

Cropping module. Each scanned page is cut at fixed pixel coordinates into 24 task images per respondent: four drawings (D1 to D4), fifteen word cells (W1 to W5, each in left hand, right hand, and uppercase), and five cursive sentences (CS1 to CS5). The scans are only read.

Preprocessing module. Each crop is converted to grayscale, its background is flattened, noise is removed with a median filter, and each task family is scaled by one fixed factor, padded with white, and inverted. No binarization, skew correction, or stretch-resizing is applied (Section 3.3).

Feature extractor. A pretrained ResNet18, fine-tuned for each task family, turns each image into a left-to-right sequence of column feature vectors from its third residual stage.

Sequence classifier. For each task family, one Gaussian HMM is trained per class. The difference between the two length-normalized log-likelihoods is converted into P(SAD) by Platt scaling.

Decision module. P(SAD) is averaged over a respondent's images within each family, and the word and cursive families are combined with equal weights. The respondent is predicted SAD when P(SAD) is at least 0.5. Drawings are analyzed separately and never fused.

Reference models. The hybrid is compared with a majority-class baseline, logistic regression on handcrafted features, logistic regression on frozen ResNet18 embeddings, and a fixed equal-weight ensemble. The CNN-HMM hybrid (v1) is the primary model; the ensemble is supporting only (Deviation 4).

Evaluation module. It runs participant-level stratified five-fold cross-validation, with macro-averaged F1-score as the primary metric, bootstrap confidence intervals, permutation tests, and Grad-CAM.

Data move one way, from the raw scans and the label export to the predictions and reports (Figures 3 and 4). Each module reads the previous module's output and writes to its own folder, so a later stage cannot change an earlier one. All splits are by respondent, so no respondent's images appear in both training and testing.

The code is written locally and kept in a GitHub repository; the Colab and Kaggle notebooks only clone it and call its modules, so the same code runs everywhere. All hyperparameters are defined in one configuration module (Table 6).

Versions of the system. Three versions share the respondents, images, labels, folds, and image backbone; they differ in what the HMMs treat as a sequence and in the unit each model learns from. Version 1 (v1), described above, reads the columns of one word or sentence image from left to right; it replaced the ensemble as the primary model after the results were known (Deviation 4). Version 2 (v2) was defined and recorded before it was run, but after the v1 results were known (Deviation 5). It reads a respondent's 24 task images in the order of the FINALE form, each represented by one frozen ResNet18 embedding, with one Gaussian HMM per class and the same folds, inner selection, and calibration rules as v1. It does not replace v1.

Version 3 (v3), added at the adviser's request (Deviation 6), models each of the 24 tasks on its own, one image per respondent, drawings included. Four models are trained per task and fold: logistic regression on handcrafted features, logistic regression on the frozen embedding, a ResNet18 fine-tuned on that task only, and the CNN-HMM on that network. It keeps the primary set, folds, labels, and 0.5 threshold, with 217 training, 39 validation, and 64 test respondents per fold. Its combinations (drawings, words, cursive, words and sentences, all 24 tasks) and one model that picks a task per fold from the validation respondents were fixed in advance. Per-task logistic regression p-values are corrected with the Benjamini-Hochberg procedure, and the CNN path has one pre-declared test, the hybrid averaged over all 24 tasks. v3 is built on the existing modules. Because v2 and v3 were added after the v1 results were known, both are exploratory and cannot change the primary conclusion. Table 13 compares the versions, and Table 15 and Figure 13 give the per-task results.

Testing the hypothesis. Either outcome counts as evidence. Chance level is measured, not assumed: the permutation test retrains the pipeline on shuffled training labels inside every fold and compares the observed macro-averaged F1-score with that null (Section 3.9). The hybrid faces the majority-class baseline and both logistic regression models on the same test respondents, so any gain must beat simple alternatives. The protocol, including folds, seed, middle band, threshold, models, and grids, was frozen before any model saw real data, and nothing is tuned or calibrated on test respondents, so the values are not inflated by leakage or by choosing the best analysis. Grad-CAM checks that the network responds to ink rather than scanning artifacts. Later changes are recorded as Deviations 4 to 6, and every model is reported in full.

Section 4.6 describes the feature extractor and sequence classifier in detail, and Chapter 5 reports the outcome of each test.

DEFENSE NOTES (not for the paper)

A. How I came up with the hypothesis

Handwriting isn't just ink on paper. It's a motor skill, so whatever state you're in when you write can show up in the trace: how big you write, the slant, the baseline, the spacing, how hard you press. EMOTHAW tested this properly and found that handwriting and drawing tasks do carry information about emotional state. But they recorded everything on a tablet, with timing and pressure.

Most handwriting in real life is on paper, though. So my question was simple: if all I have is a scanned page, is that information still there? That's my primary hypothesis: the CNN-HMM classifies unseen writers better than chance, tested with a permutation test on macro F1.

Then, since writing is produced left to right, a sequence model made sense, and CNN-HMM hybrids have worked on images with that kind of structure. Earlier offline work mostly used handcrafted features. So my secondary hypothesis was that the CNN-HMM would beat logistic regression on handcrafted features.

B. What proves the study

I want to be exact here. My primary hypothesis was not supported. The CNN-HMM got a macro F1 of 0.434, p = 0.714 over 20 retrains, with balanced accuracy 0.501. Basically it predicted HAPPY for almost everyone. My secondary hypothesis was also not supported: compared with logistic regression on handcrafted features, the difference was -0.081, with a 95% CI from -0.157 to +0.001.

What the study does show is this. Logistic regression on frozen ResNet18 embeddings separated HAPPY and SAD better than chance: macro F1 0.576, accuracy 0.578, p = 0.008. That stays significant even with a Bonferroni correction for the five pre-specified tests, where the threshold is 0.01. So a scanned page does carry a real but small signal about self-reported happy or sad state. It just got lost when I modeled the images as left-to-right sequences.

The per-exercise analysis, which is exploratory, found that no single task works on its own after correction. So the signal is spread across the whole assessment, not sitting in one drawing or one word.

Why you can trust these numbers: the protocol was frozen before any model saw real data, every split is by respondent, chance level comes from permutation nulls, and I report every model, including the ones that failed.

And some things stand no matter what the accuracy is: the FINALE dataset of 400 respondents with a self-report reviewed by four psychometricians (Cronbach's alpha 0.880), and a leak-free, reproducible pipeline that gives the first estimate of how much emotional information survives on paper for this population.

B2. v1 vs v2 vs v3

v1 is the model I proposed. It reads the columns of each word and sentence image left to right. It mostly predicted HAPPY: 153 of 174 HAPPY right, but only 18 of 146 SAD.

After seeing that, I asked whether the problem was what I was calling a sequence. The only real order in a scanned form is the order of the tasks, so v2 reads a respondent's 24 task images in form order. It did a bit better on paper, but the difference from v1 wasn't real: +0.047, with a CI that includes zero. Its HMM settings looked good on the validation respondents, 0.54 to 0.68, but dropped to 0.480 on test, so the selection was fitting noise. And plain logistic regression on the same embeddings beat it by 0.094.

v3 came from my adviser asking which tasks actually carry information. I trained everything on each task separately. Across 96 results, macro F1 ranged from 0.367 to 0.574, and nothing survived correction; the smallest q was 0.2478. Averaging the 24 per-task hybrids gave 0.371, p = 1.0.

So the takeaway is: changing what the HMM treats as a sequence never brought the signal back. The same features without sequence modeling did: 0.576, p = 0.008.

C. Likely panel questions

1. "Your primary model didn't beat chance. Why should we accept the study?"
Because the study was designed to answer a question, not to get a high number. The protocol was frozen beforehand, so the null result for the CNN-HMM is a real finding about how this kind of model handles static handwriting. And the study still found a significant signal with the embedding model, plus it delivers a new dataset and a leak-free pipeline.

2. "Why did the CNN-HMM do worse than simple logistic regression?"
My best explanation is that the column sequences vary much more between writers and between words than between happy and sad writers, so both HMMs learn the same variation and their likelihood difference says little about the label. I want to be clear that I didn't test this directly. What I can show is that the same image features carried a signal when averaged and given to logistic regression, so the signal was lost at the sequence-modeling step.

3. "How do you know the 0.576 isn't a fluke or leakage?"
Every split is by respondent, so no writer is in both training and test, and nothing was tuned on test respondents. The p = 0.008 comes from 1,000 refits on shuffled labels, and it stays below the Bonferroni threshold of 0.01 for the five pre-specified tests. It's still a small effect with a wide interval, so I describe it as an association, not a ready classifier.

4. "Why did you make v2 and v3 after seeing the results? Isn't that fishing?"
It would be fishing if I had swapped them in as the main result. I didn't. Both were written down as deviations before they ran, both are labeled exploratory, every result is reported whatever it showed, and the primary conclusion still rests on v1. In v3 I also only used the validation respondents to pick a task, and corrected the per-task tests for multiple comparisons.
